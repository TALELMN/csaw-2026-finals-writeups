# Beeseal

| Event | Category | Points | Flag |
|---|---|---|---|
| CSAW CTF Final Round 2026 | Crypto | 500 | `csaw{b33swellUNS34LED_}` |

> Beeswell Aerospace just published an internal advisory about ECDSA private-key recoverability […]
> Think you can prove private-key recoverability and decrypt the .enc file?

**TL;DR** — The signer draws ECDSA nonces from `[1, 2^248)` instead of `[1, n)`, so the top 8
bits of every nonce are zero. That is a textbook Hidden Number Problem: build the
Boneh–Venkatesan / Howgrave-Graham–Smart lattice, reduce it, and the private key falls out. The
twist is that some signatures are deliberately corrupted — one bad record destroys the lattice —
so they have to be filtered structurally and then survived statistically with random subsets.

## 2. The vulnerability

The advisory spells it out: nonces are drawn from `[1, 2^248)` rather than `[1, n)`. **Every
nonce is missing its top 8 bits.**

Start from the ECDSA signing equation and rearrange it so `d` is the unknown and `k` is small:

```
s_i · k_i ≡ z_i + d · r_i   (mod n)

  =>  k_i ≡ a_i · d + b_i   (mod n),     a_i = r_i / s_i,   b_i = z_i / s_i
```

Each `k_i` is bounded by `B = 2^248`, which is 2^8 times smaller than `n`. That makes the vector

```
(k_1, …, k_N, d·B, n·B)
```

unusually short in the lattice generated by:

```
M[i][i]     = n·n          (0 ≤ i < N)
M[N][i]     = n·a_i,       M[N][N]     = B
M[N+1][i]   = n·b_i,       M[N+1][N+1] = n·B
```

**Why reduction finds it:** all other lattice vectors contain full-size multiples of `n`, so the
one built from genuine small nonces is shorter than everything around it by roughly the bias
factor. LLL/BKZ therefore returns `±(…, d·B, n·B)`, and

```
d = sign · v_N · B⁻¹  (mod n)
```

The paper explicitly warns about the final step: forget the `B⁻¹` and you recover `d·B`, which
fails the public-key check and looks like a failed attack rather than an arithmetic slip.

Rule of thumb: an 8-bit bias needs about **32** signatures. We have far more — if they are good.

---

## 3. The twist: corrupted signatures

A single bad record poisons the lattice, because its row claims a short nonce that does not
exist, and the true short vector is no longer in the lattice at all. Two measures handle it.

### 3.1 Structural filter

A valid ECDSA `r` is the x-coordinate of a real curve point mod `n`. So check whether
`x³ + ax + b` is a quadratic residue mod `p` for each `r`:

> Records **5, 39, 42, 45, 54, 56, 78, 83, 98** have an `r` with no corresponding curve point
> and were dropped.

Record 26 only looked suspicious — its `s` string is shorter because of a missing leading zero.
It is fine, and dropping it would have been a mistake.

### 3.2 Random subsets

Some corruption is undetectable (a tampered `s` or `z` still produces a well-formed `r`). So run
the attack repeatedly on **random 40-signature subsets** of the surviving 91, doing LLL then
BKZ-20 in `fpylll`, and verify every candidate with `d·G == Q`.

Forty signatures is comfortably above the ~32 needed, and each draw has a decent chance of
being entirely clean. The 22nd subset produced a key that matched the public key:

```
d = 0xc8356b99f1e3abbc58bf973f82caabdd2444e2cbf3d71b666172b1fd8a92c29a
```

**The public key is the oracle.** Because `d·G == Q` is a free, exact check, the attack can be
made probabilistic without any risk of accepting a wrong answer.

## Takeaways

- **Partial nonce leakage is total key compromise.** Eight zero bits per nonce — a 1/256 range
  restriction that no statistical test on signatures would flag — is enough to recover a P-256
  private key from a few dozen signatures.
- **Garbage inputs are part of real lattice attacks.** Filter what you can prove invalid
  (`r` must be a curve x-coordinate), then use random subsets plus a cheap verifier for the rest.
- **Always scale back by `B`.** The lattice recovers `d·B`, not `d`. Checking against the public
  key turns this from a silent wrong answer into an obvious one.
- **Don't over-filter.** Record 26 looked malformed and was perfectly valid; a short hex string
  is a formatting artifact, not evidence of corruption.
